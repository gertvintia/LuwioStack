New package `@luwio/eid` — a framework for reading national eID smartcards from a physical reader, built as an incremental per-country registry (mirroring `@luwio/national-id`). This first release is **framework + interfaces only**: it ships no native code and does no card I/O yet. It defines the transport-agnostic domain (`Eid.read(reader, country)`), a pluggable `CardReader` / `CardSession` transport interface the app supplies, a normalized `IIdentityDocument` result model (names, national number — cross-validated via `@luwio/national-id` — birth date, sex, photo, validity, `country()`), and a per-country card-profile registry with an honest capability matrix: `Eid.accessLevel(country)` reports `open` (BE/BELPIC), `secure-channel` via CAN/MRZ/PIN (ES/IT/FR/PT), `authorization-required` (DE) or `online-only` (NL); the UK has no eID card so `GB` is unsupported. Country `read()` implementations reject with `NotImplementedError` until the real APDU/parsing (and a `@luwio/eid/node` PC/SC transport) are added. React bindings — `<Eid>` provider + `useEid()` hook with an `idle → waiting → reading → read`/`error` lifecycle — live at `@luwio/eid/react`. `@luwio/country` and `@luwio/national-id` are dependencies; React is a peer dependency.
