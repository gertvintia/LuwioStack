New package `@luwio/national-id` — typed national identification number validation for React, built as an incremental per-country registry (unlike IBAN there is no single global algorithm). `NationalId.parse(value, country)` (separators/case ignored) runs the country's scheme and throws on invalid input; instances expose `value`, `countryCode`, `country()` (a `@luwio/country` Country) and `details` — a discriminated union keyed by `countryCode` that carries only the fields a country's number actually encodes (so there are no properties left silently `null` for schemes that don't have them): `BE` → `{ birthDate, sex, isBis }`, `FR`/`IT` → `{ sex }`, and `DE`/`ES`/`GB`/`NL`/`PT` → no extras. Ships with eight countries: **BE** (Rijksregisternummer *and* BIS numbers — MOD-97, extracting birth date and sex), **DE** (Steuer-ID — ISO 7064 MOD 11,10), **ES** (DNI/NIE — mod-23 letter), **FR** (NIR/INSEE — MOD-97 key, Corsica 2A/2B), **GB** (UK National Insurance number), **IT** (Codice Fiscale — control char, omocodia, extracting sex), **NL** (BSN — 11-test) and **PT** (NIF — mod-11). `NationalId.isValid(...)` is the non-throwing check; `isSupported(...)` / `supportedCountries()` expose the registry, and unsupported countries throw `UnsupportedCountryError` (distinct from invalid). Split like the rest: React-free domain at `@luwio/national-id`, `<NationalId>` provider + `useNationalId()` at `@luwio/national-id/react`. `@luwio/country` is a dependency; React is a peer dependency.
